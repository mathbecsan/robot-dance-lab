Does a robot need a human body to dance like a human?

One dance, four bodies. The same motion is handed to a G1-style humanoid, a cheaper humanoid with fewer joints, and a single robot arm. Each is allowed only what its joints, ranges and speed limits permit. The magenta marks show where the machine could not follow.

Beat alignment is the AIST++ score minus what a random beat grid would get. It rewards simple motion: the reduced humanoid moves less, so it can look better on this number. That is a flaw of the metric, which is why the planned human rating study carries the real answer.

What this prototype is, and is not

Read before quoting any number
  • The dancer is a stand-in: a beat-locked procedural generator, not EDGE. EDGE needs a GPU and downloadable checkpoints, which the build environment did not have. A converter for EDGE's SMPL output is included and round-trip tested; swapping it in changes the human column and everything downstream follows.
  • The humanoid joint ranges are approximations inspired by Unitree G1, not read from its model file. The motion is kinematic (no physics), so "balance dot" is a conservative standing-still test, not a fall prediction.
  • Songs are original synthetic tracks, free to publish. Figures are computed from these clips; the human perception study is built but has not been run.
